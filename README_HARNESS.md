# Fast LLMs API — DeepSeek Harness Integration

Fast LLMs API exposes local GGUF, Transformers, and Ollama models through an OpenAI-compatible API and includes a DeepSeek Harness setup panel.

## English

### Start Fast LLMs API

Run:

```bat
web_api.bat
```

or:

```bat
python launcher.py
```

The launcher starts in English. Use the `Language / 语言` selector to switch between:

- `English`
- `简体中文`

### Service settings

Configure:

- Model
- API Model ID
- Context Window
- Max Output Tokens
- Service Port
- API Key

The default Base URL is:

```text
http://127.0.0.1:7021/v1
```

Available endpoints include:

```text
GET  /v1/models
POST /v1/chat/completions
GET  /health
```

Both `max_tokens` and `max_completion_tokens` are accepted by the Chat Completions endpoint.

### DeepSeek Harness

Open the `DeepSeek Harness` tab in the launcher to generate provider settings and run a compatibility test.

Typical provider values:

```text
Provider ID: fast-llms
Display name: Fast LLMs API
Base URL: http://127.0.0.1:7021/v1
API protocol: openai-completions
API Key: <key generated by the launcher>
```

The launcher can also generate a `settings.yaml` snippet:

```yaml
llm-pi-ai:
  providers:
    fast-llms:
      apiKeyEnv: FAST_LLMS_API_KEY
      displayName: Fast LLMs API
      api: openai-completions
      baseURL: http://127.0.0.1:7021/v1
      models:
        - id: "local-model"
          name: "local-model"
          contextWindow: 8192
          maxTokens: 2048
```

Start DeepSeek Harness with:

```bash
npx @deepseek-ai/dsh web
```

The compatibility test checks streaming responses, usage chunks, and structured `tool_calls`.

### Backends

GGUF uses `llama-cpp-python`. Transformers uses the tokenizer's chat template and, when available, its structured response parser. Ollama is proxied through its OpenAI-compatible Chat Completions endpoint.

Tool calling still depends on the selected model, chat template, and backend capabilities.

## 简体中文

### 启动 Fast LLMs API

运行：

```bat
web_api.bat
```

或：

```bat
python launcher.py
```

启动器默认显示英语。可以通过右上角 `Language / 语言` 在以下两种语言之间切换：

- `English`
- `简体中文`

### 服务配置

可设置：

- 模型
- API Model ID
- Context Window
- Max Output Tokens
- 服务端口
- API Key

默认 Base URL：

```text
http://127.0.0.1:7021/v1
```

可用接口包括：

```text
GET  /v1/models
POST /v1/chat/completions
GET  /health
```

Chat Completions 同时接受 `max_tokens` 和 `max_completion_tokens`。

### DeepSeek Harness

打开启动器中的 `DeepSeek Harness` 标签页，可以生成 Provider 配置并运行兼容性测试。

常用 Provider 参数：

```text
Provider ID: fast-llms
Display name: Fast LLMs API
Base URL: http://127.0.0.1:7021/v1
API protocol: openai-completions
API Key: <启动器生成的 Key>
```

启动器也可以生成 `settings.yaml` 片段：

```yaml
llm-pi-ai:
  providers:
    fast-llms:
      apiKeyEnv: FAST_LLMS_API_KEY
      displayName: Fast LLMs API
      api: openai-completions
      baseURL: http://127.0.0.1:7021/v1
      models:
        - id: "local-model"
          name: "local-model"
          contextWindow: 8192
          maxTokens: 2048
```

启动 DeepSeek Harness：

```bash
npx @deepseek-ai/dsh web
```

兼容性测试会检查流式响应、usage 数据以及结构化 `tool_calls`。

### 后端

GGUF 使用 `llama-cpp-python`；Transformers 使用 tokenizer 自带的聊天模板，并在可用时使用结构化响应解析器；Ollama 通过其 OpenAI-compatible Chat Completions 接口代理。

实际 Tool Calling 能力仍取决于所选模型、Chat Template 和后端能力。
